# 现金流日历 — 工程设计

## 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | React 19 | 组件化 UI，状态驱动 |
| 构建 | Vite 8 | 秒级 HMR，零配置 |
| 日期 | date-fns 4 | 函数式、tree-shakable，比 moment 轻 |
| 样式 | 纯 CSS | 无框架依赖，CSS 变量做主题 |
| 持久化 | localStorage | 零依赖，数据量小，单用户场景够用 |
| 图表 | 手写 SVG | 无第三方图表库，完全可控 |
| 测试 | Node 内置 test runner | engine 为纯函数，零依赖即可单测 |

## 核心架构

### 数据模型

```
AppState {
  initialBalance: number      // 初始基准余额
  events: Event[]             // 真实事件
  simulationEvents: Event[]   // 模拟事件（不影响真实数据）
}

Event {
  id, name, type, amount      // 基础和金额（amount 自带符号）
  date                        // 单次事件日期
  isRecurring, recurringType  // 周期配置
  recurringStartDate, recurringEndDate, isPermanent
  canSkip, isSimulation
  category, description      // 分类（自由文本）与备注
  skippedDates              // canSkip=true 时被跳过的具体日期（yyyy-MM-dd）
}
```

### 数据流

```
localStorage ←→ AppState
                    │
                    ▼
            engine.computeDailyBalances()
                    │
                    ▼
            cashFlowData[{date, balance, income, expense, events}]
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
  CalendarView  ChartView   BalanceInfo
```

关键设计：**所有组件只读 cashFlowData，不直接操作 state**。事件 CRUD 通过 App 层的回调函数修改 state，触发重新计算，组件自动更新。这是单向数据流。

### 引擎设计（engine.js）

引擎是纯函数模块，零 React 依赖，可独立测试。

**三步流水线：**

```
events[] → expandEvents() → datedEvents[] → computeDailyBalances() → dailyBalances[]
```

1. **expandEvents**：将周期事件展开为区间内的具体日期事件。例如"每月 1 号房租 -2000"展开为 `[{date: "2026-01-01", amount: -2000}, {date: "2026-02-01", amount: -2000}, ...]`

2. **computeDailyBalances**：按天分组事件，逐日累加余额。amount 自带符号（收入为正，支出为负），直接 `balance += amount`。

3. **getBalanceOnDate**：计算某一天的实际余额，用于校准功能。

**周期匹配规则**（matchesRecurring）：

| 周期 | 规则 |
|------|------|
| daily | 每天都匹配 |
| weekly | 星期几相同（startDate 是周三，则每个周三） |
| monthly | 日期相同（startDate 是 20 号，则每月 20 号） |
| yearly | 月日都相同 |

**可跳过单次（canSkip）**：当周期事件 `canSkip=true` 时，通过 `skippedDates`（形如 `["2026-01-03"]`）记录被跳过的具体日期。`expandEvents` 展开时若命中 `skippedDates` 中的某天则跳过该次发生。日历悬停提供"跳过本日"，事件列表展示已跳过日期并支持一键恢复。

### 组件设计

**App.jsx** — 状态管理中心：
- `useState` 管理 AppState（initialBalance + events + simulationEvents）
- `useEffect` 自动同步到 localStorage
- `useMemo` 缓存 cashFlowData 计算结果，避免重复计算
- `useCallback` 稳定化所有回调引用，避免子组件不必要的重渲染
- 计算范围：过去 90 天到未来 180 天，共 270 天

**CalendarView** — 月/周视图：
- 用 date-fns 的 `eachDayOfInterval` 生成日历网格
- 余额颜色映射：`danger(<0) / warn(<1000) / safe(>=1000)`
- 事件用小圆点表示，真实事件实心、模拟事件虚线边框
- 悬停显示当日详情栏

**ChartView** — SVG 趋势图：
- 手写 SVG，无第三方图表库
- 线性渐变填充区域，三色渐变线条
- 自动计算 Y 轴刻度（5 档），零线用红色虚线标记
- 悬停 tooltip 显示日期、余额、收支明细

**EventForm** — 事件表单：
- 受控组件，本地 state 管理表单数据
- 编辑模式回填现有数据
- 提交时自动处理 amount 符号（收入为正，支出为负）
- 周期事件显示额外配置项（周期类型、起止日期、永久/截止）
- 分类输入：`datalist` 依收入/支出给出推荐分类（见 `DEFAULT_CATEGORIES`）

**MonthlyReport** — 收支分析：
- 从 `cashFlowData` 聚合：按月的收入/支出/净额表，以及按收入/支出分类的占比条形图
- 纯展示组件，不修改任何状态

### 测试

`src/engine.test.js` 使用 Node 内置 test runner（无需安装依赖），命令：`npm test`。覆盖：normalizeEvent 默认值、单次/四类周期展开、canSkip 跳过与未开启时不生效、computeDailyBalances 累加与收支、getBalanceOnDate 校准、分类回退。
> 注：在当前受限沙箱中需以 `node --test --experimental-test-isolation=none` 运行（避免子进程 spawn）。

**SimulationPanel** — 模拟模式：
- 独立面板，复用 EventForm 组件
- 模拟事件始终带 `isSimulation: true` 标记
- 支持一键转为真实事件（复制到 events 数组，删除原 simulationEvents 条目）

**DataManager** — 数据维护：
- 导出：JSON.stringify + Blob + download
- 导入：FileReader + JSON.parse + normalizeEvent
- 校准：`getBalanceOnDate` 算当前余额，差值反推 initialBalance
- 清除：confirm 确认后重置

### 状态管理策略

没有引入 Redux/Zustand 等状态库。理由：

1. 状态结构简单：一个 AppState 对象，只有三个字段
2. 数据流单向：state → engine → cashFlowData → components
3. 无跨组件共享需求：所有状态集中在 App 层，通过 props 向下传递
4. localStorage 同步：一个 useEffect 搞定

### 性能考量

- **useMemo**：cashFlowData 计算涉及 270 天 × N 个事件的展开，使用 useMemo 在依赖不变时跳过计算
- **useCallback**：所有回调函数稳定化，避免子组件因引用变化而重渲染
- **事件展开增量**：目前每次计算都重新展开全部事件。当事件数量超过 500 个时，可考虑增量计算优化
- **SVG 渲染**：数据点 circle 元素数量 = 天数（270），在合理范围内，无性能压力

## 踩过的坑

1. **apply_patch 路径问题**：工具默认使用第一个 workspace root，导致文件写到错误目录，需要手动复制
2. **date-fns v4 导入路径**：locale 从 `date-fns/locale` 改为 `date-fns/locale/zh-CN`，v4 改了导出结构
3. **余额校准 bug**：最初只过滤了 `event.date` 字段（单次事件），忽略了周期事件的 `recurringStartDate`，导致校准完全不准。修复方式是改用 `getBalanceOnDate` 函数，它内部会正确展开所有周期事件
4. **amount 符号约定**：旧版数据中 amount 自带符号（收入正、支出负），引擎直接累加。表单提交时根据 type 自动处理符号转换
